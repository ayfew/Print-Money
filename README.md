# printmoney

**เครื่องมือหาส่วนต่างราคา (arbitrage) บนตลาด Bitcoin ของ Polymarket**
A probability-surface arbitrage engine for Polymarket's BTC price markets.

```bash
python pm.py doctor      # เช็คว่าต่อเน็ต/ติดตั้งครบไหม
python pm.py surface     # ราคาตลาด vs ราคาที่โมเดลคิดว่าถูกต้อง
python pm.py plan        # คำนวณ position ที่ควรถือ (ยังไม่ส่งออเดอร์)
python pm.py run         # เดินลูป (paper trading เป็นค่าเริ่มต้น)
python pm.py ui --serve  # หน้า dashboard ในเบราว์เซอร์ (refresh เองทุก 20 วิ)
python pm.py study       # กลยุทธ์นี้รอดค่าธรรมเนียมตัวเองมั้ย — หลักฐาน 10 ปี
python pm.py carry       # จัดอันดับ funding carry ทุก perpetual
python pm.py daily       # บรีฟเช้า: อะไรขยับ และควรทำอะไรมั้ย
```

## 1. เรื่องนี้มาจากไหน / Where this came from

โจทย์ตั้งต้นคือโพสต์บน X ที่เล่าว่ามีคนสั่ง Claude Code ว่า *"เขียนโปรแกรมให้หน่อย
นอนหลับก็ยังทำเงินได้"* แล้วได้โค้ด Rust 4,200 บรรทัดที่เทรด Polymarket
โดยเน้นตลาด **ช่วงราคา (price range)** ของ BTC ทำกำไรสะสม $480,609

**สิ่งที่ควรรู้ก่อน:** ตัวเลขกำไร รูปภาพ และเรื่องเด็ก 12 ขวบในโพสต์นั้น
ตรวจสอบไม่ได้ และในโพสต์มีลิงก์ referral ไปยัง Polymarket กับบอทชื่อ PolyCop —
มันคือคอนเทนต์ขายของ ไม่ใช่รายงานผลการทดลอง

แต่ *กลไก* ที่โพสต์อธิบายนั้นมีอยู่จริงและคำนวณได้จริง:

> ไม่ทำนายว่า BTC จะขึ้นหรือลง แต่อ่าน **ทั้งชุด** ของตลาดช่วงราคา
> แปลงเป็นการแจกแจงความน่าจะเป็น หาจุดที่ราคาตลาดไม่สอดคล้องกัน
> แล้วถือหลายขาให้หักล้างกันเอง (self-hedging grid)

repo นี้คือกลไกนั้น เขียนแบบที่ตรวจสอบได้ทุกขั้นตอน พร้อมบอกเหตุผลทุกครั้งที่
**ไม่** เทรด — ซึ่งเอาเข้าจริงคือคำตอบส่วนใหญ่

## 2. หลักการทำงาน / How it actually works

### 2.1 Strip: มองทั้งชุด ไม่ใช่ทีละตลาด

Polymarket มีตลาด BTC อยู่สามตระกูล ทั้งหมดจบที่ราคาปิดของแท่งเทียน 1 นาที
BTC/USDT บน Binance ณ เวลาที่ระบุ:

| ตระกูล | ตัวอย่าง | จ่ายเมื่อ |
|---|---|---|
| `BRACKET` | *Bitcoin price on August 26?* → `76,000-78,000` | ราคาปิดตกในช่วงนั้น |
| `ABOVE` | *Bitcoin above $80,000 on August 26?* | ราคาปิด > 80,000 |
| `TOUCH` | *Will Bitcoin reach $88,000?* | เคยแตะระดับนั้นระหว่างทาง |

สองตระกูลแรกจ่ายตาม **ราคาปิด** อย่างเดียว ดังนั้นถ้าตัดเส้นราคาที่ทุก strike
ที่ตลาดไหนก็ตามพูดถึง จะได้ *state* จำนวนจำกัด และในแต่ละ state ทุกขาจ่ายค่าคงที่
ปัญหาทั้งหมดจึงกลายเป็นปัญหาเชิงเส้น (`strategy/statespace.py`)

ตลาดที่หมดอายุพร้อมกันจะถูกแก้ **รวมกันเป็นปัญหาเดียว** — bracket strip กับ
above-ladder ของวันเดียวกันจึง hedge ข้ามตลาดกันได้

### 2.2 Fair value: จำลองเส้นทางราคาแบบเดียว ตอบได้ทุกคำถาม

`model/paths.py` สุ่มเส้นทางราคา BTC ครั้งเดียวที่ **ความผันผวน = 1 และไม่มี drift**
(เรียกว่า `PathBank`) เพราะ

```
log S_T = log S_0 + (mu - sigma^2/2) T + sigma * L_T
```

การเปลี่ยน `sigma` คือการแปลงเชิงเส้นของตัวเลขสุ่มชุดเดิม จึงได้ว่า

* ensemble 5 โมเดล = การจำลอง 1 ครั้ง ไม่ใช่ 5 ครั้ง
* การ calibrate หา sigma = binary search บน array ที่เรียงแล้ว ไม่ใช่จำลองใหม่ร้อยรอบ
* ทุกสมาชิกใน ensemble เห็นตัวเลขสุ่มชุดเดียวกัน ความต่างจึงมาจากสมมติฐาน ไม่ใช่โชค

ตัวสร้างผลตอบแทนเริ่มต้นคือ **block bootstrap** ของผลตอบแทนรายชั่วโมงจริงของ BTC
ซึ่งให้หางอ้วนและ volatility clustering มาฟรี ๆ และเพราะการ resample สร้างได้แค่
สิ่งที่เคยเกิดขึ้น จึงผสม **tail mixture** เข้าไปเล็กน้อย (ค่าเริ่มต้น 3% ของเส้นทาง
ที่ความผันผวน 2.5 เท่า) ไม่งั้นโมเดลจะตีราคาวันที่ BTC ร่วง 20% เป็นศูนย์
แล้วบอทจะยินดีขายประกันตัวนั้นให้ตลาด

จาก path bank เดียวกันอ่านได้ทั้งสามอย่าง: ราคาปิด (bracket, above) และ
ค่าสูงสุด/ต่ำสุดระหว่างทาง (touch) — ความสอดคล้องกันตรงนี้สำคัญ เพราะถ้าตัวเลข
ของเราเองขัดกัน มันจะโผล่มาเป็น "arbitrage ปลอม" แล้วเราจะเทรดมันด้วยความยินดี

### 2.3 Calibration: จุดที่แยกระหว่าง arbitrage กับการเดา volatility

**นี่คือส่วนที่สำคัญที่สุดของทั้ง repo**

ถ้าตั้งราคา BTC bucket จาก realized volatility 30 วัน แล้วซื้ออะไรก็ตามที่ดูถูก
คุณไม่ได้ทำ arbitrage — คุณกำลังเดิมพันก้อนเดียวว่า *implied vol ระยะสั้นแพงเกินไป*
โดยแต่งตัวให้ดูเหมือนเดิมพันย่อยร้อยครั้ง ตลาดคริปโตระยะสั้นมี variance risk
premium ที่ใหญ่และคงอยู่ยาว การเดิมพันแบบนี้จึงขาดทุนช้าพอที่จะดูเหมือน alpha
ได้หลายสัปดาห์ก่อนจะรู้ตัว

`model/calibrate.py` จึง fit ค่า volatility จาก **ราคาที่ตลาดเสนอทั้ง strip**
แล้ววางโมเดลที่ใช้เทรดไว้ระหว่าง implied กับ realized และบังคับให้ตำแหน่งต้องกำไร
ภายใต้ *ทั้งสอง* สิ่งที่รอดคือความไม่เห็นด้วยเรื่อง **รูปร่าง** ของการแจกแจง —
หางอ้วน ความเบ้ หรือ bucket เดียวที่ถูกไล่ราคาขึ้นเพราะลางสังหรณ์ของใครสักคน —
ซึ่งเป็นที่ที่ความไม่มีประสิทธิภาพจริง ๆ ของตลาดนี้อยู่

การ fit ใช้ *การแจกแจงเดียวกับที่เทรดจริง* ไม่ใช่ lognormal ตัวแทน ถ้าใช้ตัวแทน
ทุกขาที่ strike กลาง ๆ จะได้ "edge" ปลอมสองสามจุดเปอร์เซ็นต์ที่ชี้ไปทางเดียวกัน
ทุกรอบ แล้วมันจะกลายเป็นกลยุทธ์ไปโดยปริยาย

ตลาด `TOUCH` calibrate ได้ด้วยตัวเองผ่านสูตรปิดของ reflection principle

### 2.4 การเลือก position: linear program ไม่ใช่กฎที่เขียนมือ

โฆษณาบอทประเภทนี้พูดเหมือนกันหมดว่า *"self-hedging grid — ขึ้นก็ได้ ลงก็ได้
นิ่งก็ได้"* นั่นคือคำอธิบาย **ผลลัพธ์** ไม่ใช่วิธีทำ `strategy/lp.py` ขอผลลัพธ์นั้นตรง ๆ:

```
maximise   E[กำไร] ภายใต้โมเดลที่แย่ที่สุดที่เรายอมรับ
           - risk_aversion x CVaR(ขาดทุน)
subject to ขาดทุนใน "ทุก" state ไม่เกินเพดานที่ตั้งไว้
           เพดานเงินทุน / ต่อขา / ต่ออีเวนต์
           ไม่สั่งเกินสภาพคล่องที่ order book แสดงจริง
```

* payoff คงที่ในแต่ละ state และต้นทุนเป็นเชิงเส้นตามขนาด → เป็น LP แท้ ๆ แก้ด้วย HiGHS ในหลักมิลลิวินาที
* **instrument = หนึ่งระดับราคาใน order book** ไม่ใช่หนึ่งตลาด การกินสามระดับคือสามตัวแปรที่ต้นทุนต่างกัน ฟังก์ชันต้นทุนจึงถูกต้องเป๊ะ ไม่ใช่ประมาณ
* CVaR (`Rockafellar-Uryasev`) ยังคงเป็นเชิงเส้น จึงใส่เข้าไปในปัญหาเดียวกันได้ นี่คือสิ่งที่ทำให้เครื่องยนต์ **เลือกกำไรน้อยแต่แน่นอน แทนกำไรมากกว่าเล็กน้อยแต่ไม่แน่นอน**
* ขาที่ดูขาดทุนถ้าอยู่เดี่ยว ๆ จะถูกเก็บไว้ถ้ามันซื้อพื้นที่ความเสี่ยงคืนมาถูก ๆ ขาที่ดูน่ากินจะถูกทิ้งถ้าต้องไล่ราคาสามชั้น — ไม่มีกฎไหนถูกเขียนมือ

เพดานขาดทุนตั้งเป็น **จำนวนเงินคงที่** ไม่ใช่สัดส่วนของเงินที่ลง เพราะการซื้อขาหนึ่ง
คู่กับขาตรงข้ามคือพันธบัตรสังเคราะห์ราคาเศษสตางค์ ที่พองตัวเลข "เงินที่ลง" โดยไม่เพิ่ม
ความเสี่ยงเลย — solver จะเรียนรู้ที่จะทำแบบนั้นเพื่อซื้อโควตาขาดทุนเพิ่ม

### 2.5 ค่าธรรมเนียม: เหตุผลที่ส่วนใหญ่ไม่ควรเทรด

ตลาดคริปโตของ Polymarket ใช้ `crypto_fees_v2`:

```
ค่าธรรมเนียมต่อหุ้น = rate x min(p, 1-p)^exponent      (rate ~ 0.07)
```

ที่ `p = 0.50` คือ 3.5 เซนต์บนหุ้นราคา 50 เซนต์ — **7% ของมูลค่า ไป-กลับ**
กลยุทธ์ที่ไม่คิดตรงนี้ไม่ได้กำลังเทรด edge แต่กำลังจ่ายค่าเช่า
ทุก edge ในโค้ดนี้จึงคิด **หลังหักค่าธรรมเนียมแล้ว** และเครื่องยนต์จะปฏิเสธ
ส่วนใหญ่ของสิ่งที่ดูเหมือนโอกาส

### หน้า UI

```bash
python pm.py ui --serve          # http://127.0.0.1:8787 refresh เองทุก 20 วินาที
python pm.py ui --out report.html --no-open   # ไฟล์เดียวจบ เปิดออฟไลน์ได้
```

ดีไซน์เป็นแบบ backlit — พื้นมืด ตัวเลขเรืองแสง อ่านเร็วด้วยความสว่างไม่ใช่สี
ไม่มี JS library ไม่มี CDN ไม่มี build step ทุกอย่าง inline อยู่ในไฟล์เดียว
สิ่งที่ terminal วาดไม่ได้แต่หน้านี้วาดได้:

* **กราฟกำไร/ขาดทุนในทุก state ที่ราคาจบได้** — เห็นทันทีว่า position นี้ hedge จริง
  หรือเป็นการเดิมพันที่ใส่เสื้อคลุม hedge ไว้ แถบสีม่วงด้านล่างคือความน่าจะเป็นของ
  แต่ละช่วงตามโมเดล
* **แถบเทียบตลาด vs โมเดล รายขา** พร้อมแถบจาง ๆ ที่คือช่วงของ ensemble —
  ถ้าเส้นตลาดตกอยู่ในแถบนั้น แปลว่าเราแยกไม่ออกว่าใครถูก
* **ความเสี่ยงของ "ทั้งพอร์ต" ไม่ใช่แค่ออเดอร์ที่กำลังจะส่ง** ถ้ามี position ค้างอยู่
  ในวันหมดอายุเดียวกัน ตัวเลข worst case / CVaR จะรวมของเดิมไว้แล้ว

## 5. ความปลอดภัย / Safety

### Paper trading คือค่าเริ่มต้น

`PaperBroker` จับคู่กับ order book **จริง** คิดค่าธรรมเนียม **จริง** และตั้งใจ
มองโลกในแง่ร้ายกว่าความเป็นจริง: สมมติว่าเมื่อออเดอร์ไปถึง สภาพคล่องที่เห็นเหลือ
แค่ 90%

### การเทรดจริงต้องปลดล็อก 4 ชั้น

ต้องเป็นจริงพร้อมกันทั้งหมด ไม่งั้นระบบจะถอยไปเป็น dry run:

1. `execution.mode: live` ใน `config.yaml`
2. `live.enabled: true`
3. `live.confirm_phrase: "I ACCEPT THE RISK"`
4. `POLYMARKET_PRIVATE_KEY` ถูก export ใน shell

private key อ่านจาก environment ตอนใช้งานเท่านั้น ไม่เคยถูกเขียนลงดิสก์
ไม่เคยถูก log และไม่ถูกส่งไปที่ไหนนอกจาก client ที่เซ็นธุรกรรม
ห้ามใส่ key ลงใน `config.yaml`

ออเดอร์จริงส่งแบบ **FOK (fill-or-kill)** เพราะการได้แค่บางส่วนจะทำลาย hedge ที่
LP เพิ่งคำนวณมา

### Kill switch

| เพดาน | ค่าเริ่มต้น | ผล |
|---|---|---|
| `max_daily_loss` | 10% | หยุดจนถึงวันถัดไป |
| `max_drawdown` | 25% | หยุดถาวรจนกว่าคนจะสั่งต่อ |
| `max_gross_exposure` | 85% | ลดขนาดออเดอร์ลง |
| `max_trades_per_hour` | 60 | กันลูปพัง |
| `stale_spot_seconds` | 30 | ข้อมูลเก่าเกินไป = ไม่เทรด |

การปฏิเสธทุกครั้งมีเหตุผลเป็นประโยคเสมอ — บอทที่เงียบ ๆ ไม่เทรด แยกไม่ออกจากบอทที่พัง

## 7. กำแพงค่าธรรมเนียม / The fee wall

**นี่คือผลวิจัยที่สำคัญที่สุดในโปรเจกต์นี้** รันซ้ำได้ด้วย `python pm.py study`

คำถามคือ *"ซื้อเช้า ขายเย็น ทุกวัน จะได้กำไรมั้ย"* ทดสอบกับ 24 ตลาดกว้าง
(หุ้นสหรัฐ/ยุโรป/ญี่ปุ่น/จีน/ไทย ทองคำ เงิน น้ำมัน พันธบัตร อสังหา ดอลลาร์ BTC ETH)
ข้อมูลรายวันจริง 8.8 ปี

### ตารางเดียวที่สำคัญ

ตลาดชุดเดียวกัน ช่วงเวลาเดียวกัน **เปลี่ยนแค่ความถี่ในการเทรด**

| ถือนาน | เทรด/ปี | กำไรก่อนค่าธรรมเนียม | สุทธิ @10bp | สุทธิ @30bp |
|---|---|---|---|---|
| **1 วัน** | 252 | +8.4% | **-100.0%** | **-100.0%** |
| 5 วัน | 50 | +8.4% | +3.1% | -6.8% |
| 10 วัน | 25 | +8.1% | +5.4% | +0.3% |
| 21 วัน | 12 | +8.4% | +7.1% | +4.6% |
| 63 วัน | 4 | +8.4% | +8.0% | +7.2% |
| 252 วัน | 1 | +7.6% | +7.5% | +7.3% |

**คอลัมน์ "ก่อนค่าธรรมเนียม" แทบไม่ขยับเลย** ทุกอย่างที่เกิดกับคอลัมน์สุทธิคือค่าผ่านทาง

คนเทรดรายวันกับคนซื้อแล้วถือ **เป็นเจ้าของผลตอบแทนก้อนเดียวกัน** ต่างกันแค่คนหนึ่งจ่าย
25% ต่อปีเพื่อสิทธิ์ในการกดปุ่ม

### ทำไม 252 × 0.10% = 25.2%

เทรดวันละครั้ง = ไป-กลับ 252 ครั้งต่อปี ครั้งละ 0.10% (ค่าคอม + สเปรด แบบดีแล้ว)
กลยุทธ์ต้องทำกำไร **เกิน 25.2% ต่อปี** ก่อนหักค่าธรรมเนียม แค่เพื่อเสมอตัว

ผลจริง: ซื้อเปิดขายปิดทำได้ **+4.4%** ต่อปี

### ทางออกที่ลองแล้วไม่ได้ผล

**1. เลือกให้เก่งขึ้น** — ทดสอบกฎเลือกหุ้นรายวัน 6 แบบ

| กฎ | ก่อนค่าธรรมเนียม | สุทธิ @10bp | คำตัดสิน |
|---|---|---|---|
| เทรนด์ 20 วันแรงสุด | +11.4% | -13.4% | แยกไม่ออกจากสุ่ม |
| ตัวที่ขึ้นแรงสุดเมื่อวาน | +9.2% | -15.2% | แยกไม่ออกจากสุ่ม |
| gap up แรงสุด | +2.2% | -20.6% | แยกไม่ออกจากสุ่ม |
| ตัวที่ลงแรงสุดเมื่อวาน | +1.1% | -21.5% | แยกไม่ออกจากสุ่ม |
| gap down แรงสุด | -3.8% | -25.2% | แยกไม่ออกจากสุ่ม |

กลยุทธ์ที่**สุ่มจิ้มทิกเกอร์** 400 ครั้ง ให้ผล -10.2% ถึง +15.0% ต่อปี
ทุกกฎข้างบนตกอยู่ในช่วงนั้น — **มันไม่ใช่กฎ มันคือเหรียญที่เก็บค่าเข้าชม**

**2. เลือกตัวที่ผันผวนกว่า** — correlation ระหว่างความผันผวนระหว่างวันกับผลตอบแทน
ระหว่างวัน = **-0.48** ยิ่งเหวี่ยงยิ่งแย่ ไม่ใช่ยิ่งได้

**3. จับจังหวะ** — ถ้ารู้อนาคตว่าวันไหนควรเทรด ผลตอบแทนหลักพันเปอร์เซ็นต์
แปลว่า *ข้อมูลมีอยู่จริง* แต่ไม่มีกฎที่ทำได้จริงกฎไหนจับมันได้เลยสักกฎ

### ทางออกเดียวที่ได้ผลจริง: **เทรดให้น้อยลง**

ค่าผ่านทางต่อครั้งไม่เคยเปลี่ยน สิ่งเดียวที่ควบคุมได้คือจำนวนครั้งต่อปี

### ทดสอบ $100 ตามที่ขอ

ซื้อทุกเช้า ขายทุกเย็น ตะกร้า 20 ETF 10 ปี:

| | ผลลัพธ์ |
|---|---|
| ค่าธรรมเนียม 10bp | $100 → **$10.11** (วันกำไร 44%, drawdown -89.9%) |
| ค่าธรรมเนียม 30bp | $100 → **$0.07** |
| **ไม่ทำอะไรเลย ถือเฉย ๆ** | $100 → **$245.08** |

## 8. อะไรพยากรณ์ได้ อะไรพยากรณ์ไม่ได้

โจทย์คือ *"บอกมาว่าตัวไหนจะขึ้น ตัวไหนอันตราย"* — ครึ่งหนึ่งตอบได้ อีกครึ่งตอบไม่ได้
และความต่างนี้**วัดได้** ไม่ใช่เรื่องความเห็น

ตลาดชุดเดียวกัน 24 ตลาด 10 ปี หน้าต่างเวลาเดียวกัน รันสองครั้ง —
ครั้งหนึ่งกับความผันผวน อีกครั้งกับผลตอบแทน:

| เดือนนี้ทำนายเดือนหน้าได้แค่ไหน | correlation | เป็นบวกในกี่ตลาด |
|---|---|---|
| **ความผันผวน** | **+0.761** | **24 / 24** |
| ผลตอบแทน | +0.018 | 7 / 24 |

เรียงทุกช่วงเวลาตามความผันผวน ณ วันนั้น แล้วดูเดือนถัดไป:

| กลุ่ม | ผันผวนตอนนี้ | ผันผวนเดือนหน้า | ผลตอบแทนเดือนหน้า |
|---|---|---|---|
| สงบสุด 20% | 7.9% | **10.4%** | +0.14% |
| กลุ่ม 2 | 12.9% | **14.7%** | +0.43% |
| กลาง | 17.1% | **17.9%** | +0.45% |
| กลุ่ม 4 | 23.3% | **23.8%** | +1.09% |
| ผันผวนสุด 20% | 54.0% | **48.2%** | +3.06% |

คอลัมน์ "ผันผวนเดือนหน้า" ไต่ขึ้นตามลำดับอย่างชัดเจน — **ความเสี่ยงพยากรณ์ได้**

*(คอลัมน์ผลตอบแทนก็ไต่ขึ้นด้วย แต่นั่นคือ **ค่าชดเชยความเสี่ยง** ไม่ใช่ของฟรี —
r = +0.018 บอกว่าจับจังหวะมันไม่ได้)*

### บรีฟจึงเตือน "ระวัง" แต่ไม่บอกให้ซื้อ

```
ระวัง — ผันผวนสูงกว่าปกติของตัวเอง:
  กลุ่มสินค้าจำเป็น: ผันผวน 15% (86% ของประวัติตัวเอง) -3.9% จากจุดสูงสุดปีนี้
  น้ำมัน: ผันผวน 48% (84% ของประวัติตัวเอง) -17.5% จากจุดสูงสุดปีนี้
  อีเธอเรียม: ผันผวน 53% (82% ของประวัติตัวเอง) -26.7% จากจุดสูงสุดปีนี้
```

เทียบกับ**ประวัติของตัวมันเอง** ไม่ใช่เทียบข้ามตลาด — ผันผวน 15% คือสัปดาห์เงียบ ๆ
ของบิตคอยน์ แต่เป็นเหตุการณ์ใหญ่ของหุ้นกลุ่มสินค้าจำเป็น จีนที่ผันผวน 20% วันนี้
ถูกจัดเป็น "สงบ" เพราะมันต่ำสำหรับจีน

**สิ่งที่ไม่ได้ใส่:** อะไรก็ตามที่บอกว่าให้ซื้อตัวไหน กฎเลือกหุ้นรายวัน 6 แบบ
ทดสอบแล้วแยกไม่ออกจากการสุ่ม การเอา AI มาอ่านข่าวเพิ่มบนนั้น คือการขายสิ่งที่
โปรเจกต์นี้เพิ่งพิสูจน์ว่าไม่จริง

### 9.1 หัวข้อ "ไม่ต้องสนใจ" สำคัญเท่ากับ "จับตา"

### 9.4 บริบทมหภาค และ "ทำไมถึงขยับ"

บรีฟแสดงค่ารายวันพวกนี้ทุกเช้า และเมื่อตลาดไหนขยับเกิน 1% จะไปหาว่ามีตัวขับไหน
ขยับด้วย — **ต้องขยับแรงกว่า 70% ของการขยับปกติของตัวเอง และต้องขยับไปในทาง
ที่ความสัมพันธ์บอกว่าควรเป็น** ไม่งั้นเงียบ

วัด 192 คู่ เหลือรอด 62 คู่ ตัวอย่างที่ผ่าน:

| ตลาด | เคลื่อนไหว | เทียบกับ | r |
|---|---|---|---|
| ดอลลาร์สหรัฐ | ทางเดียวกัน | พันธบัตร 2 ปี | +0.43 |
| หุ้นกู้ผลตอบแทนสูง | สวนทาง | ผลตอบแทนแท้จริง 10 ปี | −0.43 |
| **บิตคอยน์** | **สวนทาง** | **VVIX** | **−0.34** |
| ทองคำ | สวนทาง | พันธบัตร 2 ปี | −0.21 |

บิตคอยน์เป็นตัวที่น่าสนใจสุด: คนถือเยอะเพราะเชื่อว่ามันไม่สัมพันธ์กับตลาดอื่น
ตัวเลขบอกว่ามันเป็นสินทรัพย์เสี่ยงตัวหนึ่ง ไม่ใช่ที่หลบภัย

**25 คู่ถูกตัดทิ้งเพราะเป็นเลขคณิต ไม่ใช่คำอธิบาย** — พันธบัตร 10 ปี กับ TLT
ได้ r = −0.91 แต่ TLT *คือ* พันธบัตร การบอกว่า "พันธบัตรลงเพราะ yield ขึ้น"
คือพูดเรื่องเดียวกันสองรอบ เช่นเดียวกับ VIX กับหุ้นสหรัฐ — VIX ขึ้น *เพราะ*
หุ้นลง ไม่ใช่กลับกัน

ทั้งหมดนี้เป็น correlation **วันเดียวกัน** = อธิบายสิ่งที่เกิดไปแล้ว
ไม่ได้ทำนายพรุ่งนี้ และบรีฟเขียนประโยคนั้นกำกับไว้ทุกครั้ง

```
python pm.py macro                    # ค่าวันนี้
python pm.py macro --measure --save   # วัดใหม่แล้ว commit
```

**ไม่มีชั้น "ข่าว" โดยตั้งใจ** การเอา AI มาสรุปพาดหัวข่าวแล้วบอกว่า
"ข่าวนี้บวกกับทอง" คือการเดิมพันกับ *return forecastability* ซึ่งวัดได้ที่
r = +0.02 ส่วนกำหนดการจากชั้น 1 ให้ข้อมูลเดียวกันว่า *อะไรกำลังจะมา*
โดยไม่ต้องมีใครเดาว่ามันแปลว่าอะไร

ตัวเลขความมั่นใจที่โมเดลภาษาคิดขึ้นเองไม่ได้ผ่านการ calibrate มันไม่มีความหมาย

## 11. สกอร์บอร์ด — ตัวจริงของโปรเจกต์นี้

## 12. ข้อจำกัดที่ต้องรู้ / Honest limitations

* **ส่วนใหญ่จะไม่มีอะไรให้เทรด** ค่าธรรมเนียม 7% x min(p,1-p) กินโอกาสเล็ก ๆ หมด นี่คือผลลัพธ์ที่ถูกต้อง ไม่ใช่บั๊ก
* **Paper ไม่ใช่ของจริง** มันสมมติว่าราคาที่เห็นยังอยู่ตอนออเดอร์ไปถึง จริง ๆ แล้วขาที่มี edge มากที่สุดคือขาที่หายเร็วที่สุด
* **การจำลองไม่ได้รวม drift ในค่าสูงสุด/ต่ำสุดระหว่างทาง** ผลกระทบระดับไม่กี่ basis point ต่อวัน เล็กกว่า continuity correction ที่ใส่ไปแล้วมาก แต่ก็คือการประมาณ
* **ราคาที่ใช้ทำนายมาจาก Binance** ถ้า Binance ต่อไม่ได้แล้วไปใช้ Coinbase/Kraken จะมี basis risk และระบบจะเตือน
* **ตลาด barrier พึ่งโมเดลมากที่สุด** ความน่าจะเป็นของการแตะระดับขึ้นกับ *เส้นทาง* ของ volatility ไม่ใช่แค่ค่าเฉลี่ย จึงตั้งเกณฑ์ edge ไว้กว้างกว่าและให้งบแยก
* **ไม่มีการจัดการ position ที่ถืออยู่** ระบบเปิดสถานะแล้วถือจนหมดอายุ ไม่มีการปิดก่อน ไม่มีการ roll
* **บรีฟรายวันจะบอกว่า "ไม่มีอะไร" เกือบทุกวัน** นั่นคือคำตอบที่ถูก ไม่ใช่เครื่องมือเสีย
* **`pm study` ทดสอบกฎง่าย ๆ 6 แบบ ไม่ได้พิสูจน์ว่าไม่มีกลยุทธ์ไหนได้ผลเลย** มันพิสูจน์แค่ว่า
  กฎที่คนทั่วไปนึกออกก่อนเป็นอันดับแรก แยกไม่ออกจากการสุ่ม และกำแพงค่าธรรมเนียมเป็นเลขคณิต ไม่ใช่ความเห็น
* **ทุนคือข้อจำกัดที่แท้จริง ไม่ใช่กลยุทธ์** ต่อให้ได้ 15%/ปี ซึ่งเก่งระดับกองทุน บนเงิน ฿35,000
  คือ ฿437/เดือน ไม่มีอัลกอริทึมไหนแก้เลขนี้ได้
* **ไม่ใช่คำแนะนำการลงทุน** และผมไม่ใช่ที่ปรึกษาการเงินที่มีใบอนุญาต ตลาดทำนายผลอาจผิดกฎหมายในบางเขตอำนาจ — ตรวจสอบเอง
* **สกอร์บอร์ดวัด "ทายความผันผวนถูกมั้ย" ไม่ได้วัด "ทำเงินได้มั้ย"** สองอย่างนี้ไม่เหมือนกัน
  81% คือความแม่นของการชี้ว่าความเสี่ยงอยู่ตรงไหน ไม่ได้แปลว่าเทรดตามแล้วกำไร
* **80.6% ไม่น่าแปลกใจ และนั่นคือประเด็น** volatility clustering เป็นข้อเท็จจริงที่แข็งที่สุด
  อันหนึ่งในการเงิน ตัวเลขนี้ยืนยันสิ่งที่ r = +0.76 บอกไว้แล้ว ไม่ใช่การค้นพบใหม่
* **ปฏิทินมีแค่ 2 เหตุการณ์** FOMC กับ NFP เพราะมีแค่สองอันที่หาวันได้ฟรีและวัดผ่าน
  ยังขาด CPI, ECB, BOJ, ตัวเลขจีน — ไม่ได้แปลว่าไม่สำคัญ แปลว่ายังพิสูจน์ไม่ได้
* **live scorecard ยังว่าง** เริ่มเก็บวันที่ 2026-08-26 ต้องรอ 21 วันทำการกว่าจะมีตัวเลขแรก
  ระหว่างนั้นเลขที่โชว์คือ backtest ซึ่งบอกไว้ตรง ๆ ในบรีฟว่าเป็น backtest

```
https://raw.githubusercontent.com/ayfew/Print-Money/main/reports/printmoney.ics
```

บน iPhone: **ปฏิทิน → ปฏิทิน → เพิ่มปฏิทิน → เพิ่มปฏิทินที่บอกรับ** → วาง URL ข้างบน

iPhone จะรีเฟรชเอง (ปรับความถี่ได้ที่ ตั้งค่า → แอป → ปฏิทิน → บัญชี)
ปฏิทินแบบบอกรับเป็นอ่านอย่างเดียว ซึ่งถูกต้องแล้ว — มันคือบันทึก ไม่ใช่รายการนัด

รายการแต่ละวันขึ้นหัวข้อว่า `printmoney: nothing today` หรือ
`printmoney: N to act on` กดเข้าไปอ่านเหตุผลข้างในได้

> **หมายเหตุทางเทคนิค** iCalendar บังคับใช้ CRLF ถ้า git แปลง line ending ตอน
> checkout บน Linux ไฟล์จะพังทันที `.gitattributes` เลยมาร์ค `*.ics -text`
> ไว้เป็น binary กัน git แตะ และมีเทสต์คุมทั้งฝั่งเขียนและฝั่ง commit

### สองทางในการรันงานรายวัน

| | รันที่ไหน | ต้องเปิดคอมมั้ย | ข้อดี |
|---|---|---|---|
| **Task Scheduler** | เครื่องคุณ | ต้องเปิด | มี ledger, snapshot, cache ครบ รันเอนจินเต็ม |
| **Claude Routine** | คลาวด์ | ไม่ต้อง | ปิดคอมก็ทำงาน ผลเด้งเข้าแอป Claude อ่านบนมือถือได้ |

Routine ต้องเชื่อมบัญชี GitHub กับ Claude ก่อน ไม่งั้น API จะตอบว่า
*"Connect your GitHub account before saving a routine that uses a GitHub repository."*

### ทำไมไม่ใช้ Routines ของ Claude

Routines รันบนคลาวด์ เข้าถึงเครื่องที่บ้านไม่ได้ — โค้ด ข้อมูลที่แคชไว้ และ ledger
อยู่บนเครื่องคุณทั้งหมด Task Scheduler จึงเป็นที่ที่ถูกต้องสำหรับงานนี้

Routines เหมาะกับงานคนละแบบ: ให้มันอ่านข่าว/สรุปอะไรจากเว็บแล้วส่งเข้าแอป Claude
ซึ่งเปิดอ่านบนมือถือได้เหมือนกัน แต่มันจะไม่มีข้อมูลจากเครื่องนี้

## 14. Config ที่ควรปรับก่อน

`config.yaml` มีคำอธิบายครบทุกบรรทัด ตัวที่มีผลมากที่สุด:

```yaml
risk:
  capital_usd: 1000.0          # เงินทุนที่ยอมให้ระบบใช้

strategy:
  min_edge: 0.015              # ผลตอบแทนคาดหวังขั้นต่ำต่อเงินที่ลง
  max_loss_fraction: 0.35      # x max_notional_per_event x capital = เพดานขาดทุนต่ออีเวนต์
  risk_aversion: 0.25          # น้ำหนักของ CVaR สูงขึ้น = เทรดน้อยลง hedge มากขึ้น

model:
  implied_vol_weight: 0.65     # 1.0 = เชื่อ volatility ของตลาดเต็มที่
  tail_mixture_weight: 0.03    # ฐานรองหางของการแจกแจง
  n_paths: 40000               # ลดลงถ้าอยากให้เร็วขึ้น
```

Environment variables ชนะไฟล์เสมอ: `PM_CAPITAL`, `PM_MIN_EDGE`, `PM_MODE`,
`PM_POLL_SECONDS`, `PM_PATHS`, `PM_LIVE_ENABLED`, `PM_LOG_LEVEL`
